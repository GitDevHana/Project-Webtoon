# 웹툰 편집실

기존 세로 스크롤 웹툰을 불러와 **그림·텍스트·여백을 배치하고, 고칠 곳을 표시해 다음 제작 작업으로 전달하는 로컬 편집기**입니다.

긴 원고를 통째로 펼쳐 편집하며, 이미지·편집 문서·전달본은 내 PC에 저장됩니다. 계정, API 키, 유료 API, Node.js 빌드, Python 추가 패키지가 필요하지 않습니다.

> 현재 코드는 projectWT에서 사용한 버전입니다. 독립 배포용으로 모든 프로젝트 의존성을 분리한 상태는 아닙니다. 일반 파일 불러오기와 projectWT 회차 목록 불러오기의 조건이 다릅니다. 아래 호환 범위를 먼저 확인하세요.

## 할 수 있는 일

- 긴 이미지 한 장 또는 여러 이미지를 통째로 불러오기
- 대응되는 회차 HTML, HTML과 이미지가 있는 폴더, 저장한 편집 JSON 불러오기
- 전체 원고를 세로로 보며 그림·텍스트 이동, 크기 변경, 순서·여백 조절
- 그림 이동 시 아래 원고를 함께 이동해 흐름 유지
- 그림 중간에 틈을 넣거나 추가 장면을 요청할 공간 만들기
- 텍스트 상자, 펜, 화살표, 수정 영역으로 구체적인 요청 남기기
- 원작·설정·제작 기준 파일 연결
- 작업 저장, 재불러오기, 수정 요청 전달본 만들기

이미지를 직접 다시 그리거나 AI를 자동 호출하지는 않습니다. 펜·영역·메모는 수정 지시이며, 최종 작화는 전달본을 받은 제작자가 별도로 반영해야 합니다.

## 지원 파일과 제한

| 입력 | 지원 범위 | 주의 사항 |
| --- | --- | --- |
| `.wtedit.json` | `projectWT.editor/1` 형식의 편집 문서 | 다른 프로그램의 임의 JSON·PSD·CLIP 문서와 호환되지 않습니다. |
| 편집기에서 내보낸 HTML | 편집 문서가 내장된 HTML 재불러오기 | 내장 문서가 있어야 레이어·요청을 가장 충실히 복원합니다. |
| PNG / JPEG / WebP | 긴 이미지 한 장, 여러 이미지 | 그림 속에 합쳐진 글자는 이미지의 일부입니다. |
| GIF | 브라우저가 읽을 수 있는 이미지로 불러오기 | 애니메이션 편집·프레임 보존은 검증하지 않았습니다. 정지 이미지 사용을 권장합니다. |
| 일반 HTML | `<img>`가 있는 원고를 추출 | 모든 웹페이지의 CSS·레이아웃·대사를 그대로 재현하는 범용 HTML 편집기는 아닙니다. |
| 구조화된 회차 HTML | `.scene[data-cut]` 또는 `.scene[id]` 안의 그림과 대응 식자 | 프로젝트 형식에 따라 분리 수준이 달라집니다. 불러온 뒤 위치·텍스트를 확인하세요. |
| 상대경로 이미지가 있는 HTML | **외부 회차 폴더 불러오기**로 HTML과 이미지를 함께 선택 | HTML 파일만 선택하면 그림이 누락될 수 있습니다. 폴더 내부 경로를 유지하세요. |
| MD / TXT | 작품별 제작 기준·원작·설정의 참고 파일 연결 | 텍스트를 자동 각색하거나 내용의 사실 여부를 판단하지 않습니다. |

다음 형식은 지원 대상으로 보장하지 않습니다.

- PDF, PSD, CLIP, EPUB, ZIP 직접 불러오기
- `<canvas>` 또는 인라인 SVG만으로 그린 HTML, CSS 배경 이미지만 사용하는 페이지
- 스크립트를 실행해야 원고가 나타나는 웹앱, 외부 URL 원고 자동 수집
- 외부 웹폰트·CSS·JavaScript까지 포함한 웹페이지의 완전한 복제
- 그림에 합쳐진 말풍선·글자를 자동 분리하거나 OCR로 재식자하는 작업

**이미지 안의 글자는 따로 선택할 수 없습니다.** 해당 부분에 영역·메모를 남겨 수정 요청하세요. 반대로 실제 텍스트 레이어가 있는 문서는 텍스트 위치와 내용을 편집할 수 있습니다.

SVG 중심으로 조립된 감상용 HTML은 화면에서 잘 열려도 편집기 재불러오기와는 별개입니다. 이런 경우 원래 편집 JSON 또는 개별 이미지로 불러오세요.

## 실행 환경과 호환성

| 항목 | 현재 상태 |
| --- | --- |
| 검증한 환경 | Windows, Python 3.14, 데스크톱 Google Chrome |
| 서버 | Python 표준 라이브러리 기반. 별도 패키지 설치 없음 |
| 권장 브라우저 | 데스크톱 Google Chrome |
| Edge / Firefox / Safari | 현재 버전의 실제 동작 검증 없음 |
| macOS / Linux | 실제 실행 검증 없음. Windows 실행용 `.cmd`는 사용할 수 없습니다. |
| 휴대폰 / 태블릿 편집 | 실제 터치 조작 검증 없음. 마우스 중심 UI입니다. |
| 인터넷 | 로컬 편집에 외부 서비스 연결이 필수는 아닙니다. GitHub 업로드는 별도 작업입니다. |

원고의 이미지 수·해상도·내장 데이터에 따라 브라우저 메모리와 저장 용량을 많이 사용할 수 있습니다. 이미지와 기준 파일이 문서에 함께 들어가므로 저장 JSON·전달 HTML은 원본 이미지 합계보다 커질 수 있습니다. 최대 원고 크기나 저사양 PC의 원활한 작동은 보장하지 않습니다. 서버의 JSON 요청 한도는 150MiB입니다.

### projectWT 회차 목록의 추가 조건

현재 `importer.py`는 **편집기 폴더의 상위 폴더를 프로젝트 루트**로 사용합니다. 다음 구성을 기준으로 작성되었습니다.

```text
project-root/
├─ editor/                      # 이 저장소의 코드
│  ├─ server.py
│  ├─ importer.py
│  └─ ...
├─ episodes/
│  ├─ EP01/
│  │  ├─ EP01_manifest.json
│  │  ├─ EP01_reader.html
│  │  └─ assets/...
│  └─ ...
├─ references/                  # 선택 사항
├─ memory/                      # 선택 사항
├─ AGENTS.md                    # 선택 사항
└─ PROMPT.md                    # 선택 사항
```

- 회차 목록은 `episodes/EPXX/EPXX_manifest.json`과 `EPXX_reader.html`에 대응합니다. 임의 폴더의 모든 웹툰을 자동 인식하지 않습니다.
- **회차 목록의 최초 불러오기**에는 현재 `episodes/EP03/review/cdp.py` 보조 코드와 Windows 기본 경로에 설치된 Google Chrome이 필요합니다.
- 이 보조 코드와 실제 회차 자료는 편집기 코드만 올리는 저장소에 포함되지 않습니다. 따라서 새 PC에서 저장소만 받으면 projectWT 회차 목록 기능까지 바로 동작하는 것은 아닙니다.
- 일반 이미지·대응 HTML·편집 JSON을 화면의 **원고 통째로 불러오기**로 여는 기능은 위 회차 가져오기 보조 코드를 사용하지 않습니다.
- 회차 자료가 없는 환경에서는 회차 선택 대신 **원고 통째로 불러오기**를 눌러 시작하세요.

## 시작하기

### Windows

1. Python을 설치하고 `python --version`으로 실행 여부를 확인합니다.
2. `start_editor.cmd`를 더블클릭합니다.
3. 브라우저가 열리면 `http://127.0.0.1:8765/`에서 작업합니다.

직접 실행하려면 편집기 폴더에서:

```bash
python server.py --open
```

다른 포트를 사용하려면:

```bash
python server.py --port 8766 --open
```

서버는 `127.0.0.1`에만 연결됩니다. 다른 사람에게 이 주소를 보내도 상대 PC에서 내 편집기에 접속할 수는 없습니다. 인터넷에 공개하는 서비스나 다중 사용자 협업 서버로 구성된 프로그램은 아닙니다.

실행 중인 서버를 종료하면 서버 저장 기능도 멈춥니다. 터미널에서 실행한 경우 `Ctrl+C`로 종료할 수 있습니다.

## 기본 사용법

1. **불러오기**: 로컬 회차를 선택하거나 **원고 통째로 불러오기**에서 이미지·HTML·편집 JSON을 선택합니다. 상대경로 HTML은 **외부 회차 폴더 불러오기**를 사용합니다.
2. **배치하기**: 그림·글자를 선택해 이동하거나 크기를 조절합니다. 원고를 스크롤하며 앞뒤 연결을 확인합니다.
3. **수정 표시하기**: 영역을 지정하고 구체적으로 적습니다. 예: “이 얼굴에 승인 디자인의 수염만 추가. 표정·구도·옷은 유지.”
4. **중간 저장하기**: 계속 편집하려면 **작업 저장**을 누릅니다.
5. **다시 열기**: **저장한 작업**에서 저장본 또는 브라우저 복구본을 고릅니다. 내려받은 `.wtedit.json`도 다시 불러올 수 있습니다.
6. **전달하기**: 수정 표시를 마치면 **편집 완료**를 누릅니다. 완료 화면의 경로·요청 문구를 제작자에게 전달합니다.

### 도구

| 도구 | 키 | 동작 |
| --- | --- | --- |
| 선택 | V | 그림·텍스트 선택과 이동 |
| 텍스트 상자 | T | 네모 영역에 텍스트 입력. 기본은 수정 요청 메모 |
| 펜 | P | 자유 선으로 수정 의도 표시 |
| 화살표 | A | 수정 대상이나 이동 방향 표시 |
| 수정 영역 | R | 영역을 지정하고 자연어 요청 작성 |
| 틈 넣기 | G | 원하는 위치에 여백 삽입 |
| 컷 추가 | N | 추가 장면을 요청할 공간 삽입 |
| 실행 취소 | Ctrl+Z | 이전 편집으로 돌아가기 |
| 다시 실행 | Ctrl+Shift+Z | 취소한 편집 다시 적용 |

텍스트 상자를 실제 원고 내용으로 넣으려면 오른쪽의 **수정 요청 메모** 체크를 끕니다. 펜·화살표·영역 표시는 기본적으로 지시입니다. 감상 보기에서는 지시가 숨겨지고, 전달용 미리보기에는 지시가 포함됩니다.

### 원고 이동과 틈

- **그림 이동 시 아래 원고도 함께**가 켜져 있으면 아래 내용도 함께 이동합니다. 위로 끌면 앞의 틈을 가능한 만큼 줄입니다.
- 체크를 끄면 선택한 요소를 개별 이동합니다.
- 원고 왼쪽 ↕ 손잡이로 구간 간격을 조절할 수 있습니다.
- 그림 중간에 틈을 넣으면 원본 이미지 데이터는 유지하고 표시 구간을 나눕니다. 분할 조각·여백을 새 그림이나 새 서사 컷으로 세지 않습니다.
- 추가 컷 공간은 실제 작화가 아니라 제작 요청입니다.

## 저장은 어떻게 되나요?

**원본 회차 HTML·그림·manifest를 편집기로 덮어쓰지 않습니다.**

| 방식 | 저장 위치 | 의미 |
| --- | --- | --- |
| 자동 복구 | 해당 브라우저의 IndexedDB | 사고에 대비한 복구본. 파일 백업을 대신하지 않습니다. |
| 작업 저장 | 편집기 폴더의 `saves/*.wtedit.json` | 날짜·마이크로초·임의 ID가 붙은 새 편집 파일. 저장 후 계속 편집할 수 있습니다. |
| 서버 저장 실패 시 다운로드 | 브라우저가 지정한 다운로드 위치 | 다운로드가 실제 끝났는지 사용자가 확인해야 합니다. |
| 편집 완료 | `handoff/<고유 이름>/` | 문서·변경 내역·수정 표시·제작 기준을 묶은 새 전달 폴더 |

작업 저장과 편집 완료는 매번 새 파일 또는 폴더를 만듭니다. `handoff/latest.json`은 최신 전달 경로를 가리키는 목록이라 갱신되지만, 이전 전달 폴더는 남습니다.

브라우저 자동 복구는 같은 브라우저 프로필과 주소를 기준으로 합니다. 시크릿 모드 종료, 사이트 데이터 삭제, 다른 브라우저·포트 사용 등으로 이전 복구본이 보이지 않을 수 있습니다. 중요한 시점에는 작업 저장이나 파일 다운로드를 사용하세요.

다른 원고로 전환할 때도 복구본을 보관하려고 시도합니다. 저장 공간 부족·브라우저 제한·서버 오류가 나면 실패 안내를 확인해야 합니다.

### 편집 완료로 만들어지는 파일

```text
handoff/<고유 이름>/
├─ document.wtedit.json   # 이미지·레이어·요청이 들어 있는 편집 문서
├─ revision.json          # 원본 대비 변경 내역과 수정 지시
├─ preview.html           # 수정 표시가 포함된 전달용 미리보기
├─ handoff.json           # 전달 메타데이터
└─ README_APPLY.md        # 다음 제작 작업의 반영 지침
```

- **편집 완료를 누르는 것만으로 AI가 작업을 시작하지 않습니다.** 다음 제작 작업에서 해당 전달본을 읽어 실제 수정·검수를 해야 합니다.
- 같은 PC의 제작자에게는 완료 화면의 경로와 요청 문구를 전달하면 됩니다.
- 다른 PC로 전달할 때는 로컬 경로 문자열만 보내면 안 됩니다. 전달 폴더 또는 내려받은 편집 파일을 함께 보내세요. 원작·참고자료가 별도 경로로만 연결됐다면 필요한 자료도 확인해야 합니다.
- `preview.html`은 수정 지시를 확인하는 미리보기입니다. 실제 그림 수정까지 끝난 최종 웹툰과 구분하세요.

## 다른 작품과 제작 기준

**제작 기준**에서 해당 작품의 AGENTS.md·PROMPT.md·설정 파일을 연결하고 확인할 수 있습니다. 서로 다른 작품은 문서 ID로 구분하며, 같은 회차 번호라고 해서 동일 문서로 취급하지 않습니다.

편집기는 기준 파일을 저장·전달하지만 원작의 사실 관계, 인물 정체성, 그림체 일관성을 자동으로 검수하지는 않습니다. 최종 반영 작업에서 최신 원작·설정을 다시 확인해야 합니다. 실제 발화·생각·독백·해설의 최종 식자 구분도 제작 단계에서 결정합니다.

## 확인된 한계와 미완료 항목

- 회차 가져오기 보조 코드가 웹툰 폴더에 남아 있어 회차 목록 기능은 완전히 독립 배포된 상태가 아닙니다.
- **초기 불러오기 시 배경 → 그림 → 말풍선이 자연스럽게 겹치도록 배치하는 개선은 미완료**입니다. 원본 식자가 그림 앞뒤 공간으로 들어오는 경우가 있습니다. 레이어 순서와 실제 위치는 별도로 확인하세요.
- 그림 안에 합쳐진 글자는 독립 텍스트처럼 편집할 수 없습니다.
- SVG 중심 감상용 HTML, 임의 사이트의 화면 구성, 외부 리소스는 완전한 호환을 보장하지 않습니다.
- 그림 생성·부분 작화·원작 의미 검수는 자동 수행하지 않습니다.
- 데스크톱 Chrome 이외 브라우저와 실물 모바일의 동작은 미검증입니다.

## 검증 기록과 개발

현재 프로젝트에서 백엔드와 데스크톱 Chrome UI·연속 원고·경계 조건을 검사한 이력이 있습니다. 이는 해당 Windows 환경에서의 검증이며, 모든 환경·파일 형식에 대한 보증은 아닙니다.

아래 통합 검사는 실제 projectWT 회차·설정·Chrome 보조 코드가 있는 개발 환경을 전제로 합니다. 코드만 내려받은 새 환경에서 바로 실행 가능한 독립 테스트 묶음은 아닙니다.

```bash
python test_backend.py
python test_editor_ui.py
python test_continuous.py
python test_continuous_edges.py
```

검사용 이미지·브라우저 프로필·결과는 `review/`, 가져오기 캐시는 `cache/`에 생성됩니다. 사용자 저장본과 검사용 데이터는 구분해서 보관하세요.
