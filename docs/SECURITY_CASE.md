# 독자 업로드 사이트의 파일 공개와 용량 경합

웹툰 업로드 서비스에서 파일 URL이 난수라는 이유만으로 공개 여부를 판단하면, 미게시 파일이나 삭제된 회차의 파일을 URL만으로 열 수 있습니다. 업로드 전 잔여 용량을 읽고 나중에 저장하는 방식은 동시 요청 두 개가 같은 여유 공간을 쓸 수도 있습니다.

공개한 실제 구현의 핵심은 다음과 같습니다.

| 문제 | 코드 | 공개 검증 |
| --- | --- | --- |
| 미게시·삭제 파일 URL 접근 | `lib/security.mjs`의 `isPublishedFile`, `lib/community.mjs`의 `/files/:id` 처리 | 게시 참조 없음/있음의 판정 |
| 동시 업로드 용량 경합 | `lib/security.mjs`의 `reserveUpload`: 용량 비교와 예약을 단일 SQLite 쓰기문으로 결합 | 같은 잔여 공간에 병렬 예약 시 한 건만 성공 |
| 계정별 요청 제한 | `lib/security.mjs`의 `enforceRate`: D1에 창별 카운트 UPSERT | 한도 초과 429, 사용자 분리, 다음 창 초기화 |
| 개인정보가 남는 감사 기록 | `lib/security.mjs`의 `audit`: 고정 이벤트·가명 ID·상태만 기록 | 저장 데이터에 메일·쿠키·원고 제외 |

`node site-security/test-public.mjs`는 Node의 내장 SQLite를 써서 공개 핵심 함수를 검증합니다. 실제 사이트에서는 API 핸들러, D1, R2, 인증 경계를 함께 사용합니다. 비공개 운영 데이터와 실제 로그인 세션은 공개 예제에 포함하지 않았습니다.

이 사례의 범위는 새 업로드 파일입니다. 과거에 이미 공개 정적 자산으로 배포한 원고, 이전 다운로드·캐시, 저장소와 DB의 모든 경합, 분산 DDoS, 외부 침투 테스트는 이 코드만으로 해결했다고 주장하지 않습니다. 인증 신원 헤더의 무결성은 호스팅 플랫폼의 인증 경계에 의존합니다.
